Why Prompt Engineering Is A Real Skill

“A great prompt is worth a thousand lines of documentation.”

Your prompts determine the quality of AI output. Two engineers on the same team, same model, same problem — one ships in 20 minutes, the other struggles for 3 hours. The difference is almost always prompt quality.

The R-C-T-F Framework

🎭

R — Role

Who should the AI pretend to be? "Senior Laravel engineer with 10 years..."

📋

C — Context

What project, stack, constraints, existing code?

✅

T — Task

What exactly do you want done? Be specific.

📐

F — Format

JSON? Markdown? Numbered list? A code file only?

Weak Prompt vs Strong Prompt

prompt
❌ WEAK:
 "Make me a login form"
prompt
✅ STRONG:
ROLE: You are a senior React + TypeScript engineer.
CONTEXT: I am building a SPA with Next.js 15, TailwindCSS 4, and
         the <shadcn/ui> component library. Auth is handled by Clerk.
TASK: Create a login form component at
         src/components/auth/LoginForm.tsx with:
         - email + password fields (react-hook-form + zod validation)
         - "Remember me" checkbox
         - submit button with loading spinner
         - red error text under each invalid field
         - link to /forgot-password
FORMAT: Return only the .tsx file contents — no prose, no imports
         from libraries I didn't mention.
ObserveStrong prompts take 30 seconds to write and save 30 minutes of rework.

Chain-of-Thought For Hard Problems

prompt
I have 37 apples. I give 12 to Bob and buy 9 more.
How many do I have now? Think step by step.

Step 1: Start with 37
Step 2: Give away 12  → 37 - 12 = 25
Step 3: Buy 9 more    → 25 + 9 = 34
Answer: 34

Use this for anything involving: algorithms, refactoring decisions, debugging, or architectural choices.

System Prompts & Personas

System prompts set long-term behaviour. In Cursor and the Claude API you can set one that persists across the whole session.

prompt
You are a senior TypeScript engineer at a fintech startup.

Rules you must ALWAYS follow:
1. Never suggest any library not listed in package.json.
2. Prefer async/await over .then chains.
3. Throw typed errors, never plain strings.
4. Add a JSDoc comment to every exported function.
5. When you change a file, show a full diff, not just the change.
6. If I ask for code you are not confident about, ask a
   clarifying question first.

The Five Anti-Patterns To Avoid

  1. 1Vague verbs ("fix it", "make it nice")
  2. 2Hidden context ("My code doesn't work" — without showing the code or the error)
  3. 3Asking for 10 features in one prompt — the AI will forget half of them
  4. 4Accepting output without reading it
  5. 5Blaming the AI for a bad output that came from a bad prompt

The "Clarifying Question" Move

Before asking for code, instruct the AI to ask clarifying questions first.

prompt
ME:  Build me a blog.
      BEFORE writing code, ask me 5 clarifying questions.

AI:  1. Who is the audience? (consumer/developer/enterprise)
     2. Should posts support comments and if so, auth required?
     3. Do you want Markdown or a WYSIWYG editor?
     4. Which stack: Laravel, Next.js, or WordPress?
     5. Where will it be hosted?

ME:  1. Developers  2. Comments via GitHub OAuth
     3. Markdown    4. Next.js    5. Vercel

AI:  (writes a perfect starter project)

AI For Code Review

prompt
Act as a strict senior code reviewer.
Review the following function for:
  (1) correctness bugs
  (2) security issues (SQLi, XSS, auth)
  (3) performance problems
  (4) readability

For each issue: quote the line and suggest the fix.
If the code is clean, reply 'LGTM' and nothing else.

<code>
function login(req) {
  const user = db.query(
    'SELECT * FROM users WHERE email = "' + req.body.email + '"'
  );
  if (user.password === req.body.password) return user;
}
</code>
The AI will catchSQL injection + plaintext password compare + no return-null case — three bugs in 4 lines!

Context Attachment Patterns in Cursor

  • ▶@file — attach the currently selected file
  • ▶@symbol — attach a specific function/class by name
  • ▶@codebase — attach the entire project (use sparingly)
  • ▶@docs — attach pinned library docs
  • ▶@web — have the AI browse the live internet
  • ▶@git — attach recent git diff for PR review prompts

Ethics & Hallucinations

AI Lies ConfidentlyLLMs sometimes invent function names, library APIs, and docs that do not exist. This is called hallucination.
DefenceAlways verify: run the code, check the docs, ask the AI "are you sure this API exists in version X?".
PrivacyNever paste private customer data. Use the enterprise/offline model tier for sensitive code.
