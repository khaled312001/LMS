What Is Git (and What It Is Not)

✅

Git IS

A distributed version-control system that tracks every change to every file.

❌

Git is NOT

GitHub, GitLab, or Bitbucket — those are hosting platforms built around Git.

You can use Git 100% offline. GitHub adds collaboration, issues, Pull Requests, Actions, and backup.

Installing & Configuring Git

The Three States: Working Directory → Staging → Repository

bash
# 1) Modify a file
echo 'console.log("hi")' > index.js

# 2) See it:
git status
# → modified:   index.js

# 3) Stage it (add to the "about to commit" list)
git add index.js

# 4) Commit it (snapshot to the repo)
git commit -m "feat: add greeting"

# 5) Push to GitHub
git push origin main

Pushing An Existing Folder To GitHub

bash
cd my-project
git init
echo 'node_modules/' > .gitignore
git add .
git commit -m "chore: initial commit"
git branch -M main
git remote add origin git@github.com:alice/my-first-repo.git
git push -u origin main
The -u flagSets this branch to always track origin/main — subsequent pushes are just git push.

Branching — The Developer's Superpower

A branch is an independent line of work. You can experiment freely without touching main.

bash
# Create and switch in one go
git checkout -b feature/shopping-cart

# work work work...
git add .
git commit -m "feat(cart): add quantity stepper"

# Push the branch
git push -u origin feature/shopping-cart

# When merged on GitHub, delete locally
git checkout main
git pull
git branch -d feature/shopping-cart

Pull Requests — The Review Ritual

  1. 1Push your feature branch to GitHub
  2. 2Open a Pull Request from feature/x into main
  3. 3Write a clear description: what + why + how to test
  4. 4Assign reviewers; they leave comments on specific lines
  5. 5CI runs tests automatically
  6. 6You push fixes; the PR updates automatically
  7. 7Reviewer approves → you click "Squash and merge"

Resolving Merge Conflicts (Without Panicking)

A conflict happens when two branches edit the same lines differently. Git marks them:

diff
<<<<<<< HEAD
const price = 99.99;
=======
const price = 79.99;
>>>>>>> feature/discount
  1. 1Open the file — VS Code highlights both versions
  2. 2Pick the right one, or combine them
  3. 3Remove the <<<< markers
  4. 4git add <file>
  5. 5git commit (Git writes a merge commit for you)

GitHub Actions — CI/CD In 20 Lines

yaml
.github/workflows/test.yml

name: Tests
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - run: npm test

Push this file and every future push runs your tests. Free for public repos.

Undoing Things Safely

SituationCommand
Unstage a filegit restore --staged file
Discard local changes to a filegit restore file
Amend the last commit messagegit commit --amend
Undo last commit (keep changes)git reset --soft HEAD~1
Undo last commit (nuke changes)git reset --hard HEAD~1
Revert a published commitgit revert <sha>
Throw away all local stategit reset --hard origin/main
Golden ruleNever reset --hard on a branch other developers rely on. Use revert.

A Professional Branch Strategy (GitHub Flow)

  1. 1main is always deployable
  2. 2Every feature gets a branch named feat/*, fix/* or chore/*
  3. 3Open a Pull Request from day one (even with partial work) and mark it Draft
  4. 4At least one reviewer must approve
  5. 5Squash-merge into main; delete the branch
  6. 6Tag releases with semantic versions (v1.2.0)
